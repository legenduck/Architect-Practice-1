# 실습 1 수강생 사용 시나리오

수강생은 **작업 지침을 개선하고, 기능 정확도를 유지하면서 입력 토큰이 줄었는지 확인**합니다. 기능 구현과 결과 제출은 실행 도구가 처리합니다.

이 안내는 강사가 공통 환경과 자동 채점을 준비한 실습 폴더를 기준으로 합니다. 수업 전에 Codex CLI 로그인, GitHub 초대 수락과 Git 인증을 마칩니다. 참가자 번호와 전체 결과 화면 주소는 강사에게 안내받습니다. 아래의 `p01`은 예시입니다.

## 진행 순서

```text
준비 확인 → 시작 파일 실행 → 참가자 번호 입력
    → 1번 기본 지침 실행 → 2번 Progressive disclosure 실행
    → 6번 채점 수신 → 4번 결과 비교
    → edit/AGENTS.md 수정 → 3번 직접 개선 실행
    → 5번 기법·메모 기록 → 6번 채점 수신 → 4번 결과 비교
    → 필요하면 지침 수정부터 반복 → 결과 공유 → 0번 종료
```

| 메뉴 | 하는 일 |
|---|---|
| 1 | 기본 지침으로 구현하고 결과 제출 |
| 2 | 제공된 Progressive disclosure 지침으로 구현하고 결과 제출 |
| 3 | 직접 수정한 지침으로 구현하고 결과 제출 |
| 4 | 내 실행 결과 화면 열기 |
| 5 | 최근 실행의 기법·메모 기록 또는 재제출 |
| 6 | 서버의 채점 결과를 가져와 내 결과 화면 갱신 |
| 7 | 준비 상태 다시 확인 (`doctor`) |
| 0 | 종료 |

## 1. 실습 준비 확인

준비된 실습 폴더에서 터미널을 열고 운영체제에 맞는 명령을 실행합니다.

| 환경 | 준비 확인 명령 | 실습 시작 방법 |
|---|---|---|
| Windows | `.\start.bat doctor` | `start.bat` 실행 |
| macOS | `./start.command doctor` | `start.command` 실행 |
| Linux | `./start.command doctor` | 터미널에서 `./start.command` 실행 |

필요한 Python 패키지가 자동으로 준비되고, 도구·로그인·샌드박스·Git 제출 접속·채점 결과 수신 경로를 점검합니다. `doctor`는 모델을 호출하지 않습니다.

- 모두 `[OK]`이면 시작 파일을 실행합니다.
- `[FAIL]`이 있으면 표시된 안내를 확인하고, 해결되지 않으면 `doctor.log`를 강사에게 전달합니다.

시작할 때도 준비 상태를 자동으로 확인합니다. 최초 실행에서는 배정받은 참가자 번호를 입력합니다.

```text
배정받은 참가자 번호: p01
```

이후 같은 폴더에서 다시 시작하면 참가자 설정, 수정한 지침과 실행 기록을 유지합니다.

## 2. 기본 지침으로 기준 결과 만들기

메뉴 **1번: 기본 지침 실행·제출**을 선택합니다.

도구가 초기 코드와 기본 작업 지침을 준비하고, 새 Codex 대화에서 쿠폰 기능 구현을 요청합니다. 실행이 끝나면 결과가 자동 제출되고 메뉴로 돌아옵니다. 이후 실험은 이 기록을 기준으로 비교합니다.

실행 중에는 진행 로그의 위치가 표시됩니다. 정상 제출 후에도 채점이 끝나기 전까지는 `채점 대기`로 표시될 수 있습니다. **실행 종료, 제출 완료, 채점 통과는 각각 다른 상태**입니다.

## 3. 제공된 개선 지침과 비교하기

메뉴 **2번: Progressive disclosure 실행·제출**을 선택합니다.

이번에는 문서 목록과 조회 시점을 안내하는 지침을 사용합니다. 같은 과제와 초기 코드에서 다시 시작하므로 수강생이 코드를 초기화할 필요는 없습니다.

실행 후 **6번**으로 채점 결과를 가져오고 **4번**으로 결과 화면을 확인합니다. 브라우저가 자동으로 열리지 않으면 실습 폴더의 `results.html`을 직접 엽니다. 이미 열어 둔 화면은 새로고침합니다.

| 확인할 항목 | 살펴볼 내용 |
|---|---|
| 채점 | 두 실행 모두 통과했는가? |
| 비교 | 동일한 실행 조건으로 `가능`이라고 표시되는가? |
| 총 입력 토큰 | 기본 지침보다 줄었는가? 캐시 입력은 총량에 이미 포함된다. |
| 호출별 입력 토큰 | 어느 호출에서 입력량이 늘었는가? 세부 기록이 없으면 추정하지 않는다. |
| 문서 경로·명령 기록 | 불필요한 문서 조회나 긴 출력이 반복되는가? |

채점 대기 중에도 다음 단계로 진행할 수 있습니다. 절감 효과에 대한 판단은 채점 통과를 확인한 뒤 합니다. 명령에 나타난 문서 경로만으로 실제 읽은 범위 전체를 단정하지 않습니다.

## 4. 관찰한 문제 하나를 골라 지침 수정하기

예를 들어 테스트 성공 로그가 반복해서 입력되는 것을 보고, **테스트 출력 줄이기**를 적용한다고 가정합니다. 처음에는 한 가지 기법씩 바꾸면 효과를 해석하기 쉽습니다.

실행 메뉴는 그대로 두고, 실습 폴더에서 새 터미널을 열어 지침 편집용 Codex를 실행합니다.

```bash
cd edit
codex
```

다음처럼 요청합니다.

> 이 폴더의 AGENTS.md를 수정해줘. 과제 실행 시 전체 테스트는 유지하면서 `python tools/test_summary.py`를 사용하도록 지시해줘. 통과하면 상세 성공 로그를 다시 읽지 않고, 실패하면 저장된 로그에서 실패 원인을 확인하도록 해줘. 나머지 작업 지침은 유지해줘.

변경된 `edit/AGENTS.md`를 확인하고 저장합니다. 이 편집 대화의 토큰은 과제 실행 측정에 포함되지 않습니다.

다른 개선 방향은 [기법별 적용 힌트](techniques.md)를 참고합니다. 필요한 경우 스킬은 `edit/.agents/skills/`에 작성합니다. 직접 개선 실행에는 이 지침과 스킬이 반영되며, 구현 코드는 매번 초기 상태에서 준비됩니다.

## 5. 직접 개선한 지침 실행과 기법 기록

실행 메뉴로 돌아와 **3번: 직접 개선 실행·제출**을 선택합니다. 도구가 저장한 지침으로 새 구현을 수행하고 결과를 제출합니다.

실행 후 **5번**을 선택해 적용한 기법과 변경 내용을 기록합니다.

```text
적용한 기법(쉼표 구분, Enter로 유지): 테스트 출력 줄이기
변경 내용(Enter로 유지): 전체 테스트를 유지하고 성공 로그는 요약만 확인
```

여러 기법은 쉼표로 구분합니다. 빈 입력은 기존 값을 유지합니다. **5번은 가장 최근 실행을 대상으로 하므로**, 각 개선 실행 직후 기록하면 어떤 지침을 바꿨는지 구분하기 쉽습니다.

기법·메모를 변경하면 제출 파일이 갱신되어 다시 채점합니다. 잠시 `채점 대기`로 표시되는 것은 정상입니다. 모델 구현을 다시 실행하는 과정은 아닙니다.

## 6. 결과를 보고 반복하기

**6번**으로 채점 결과를 가져온 뒤 **4번**에서 기본 지침, 제공된 개선 지침, 직접 개선한 지침을 비교합니다.

| 결과 | 다음 행동 |
|---|---|
| 통과했고 토큰이 줄었음 | 효과를 기록하고 다음 개선을 시도한다. |
| 통과했지만 토큰이 늘었음 | 호출·문서 조회·명령 기록에서 원인을 살핀다. |
| 채점 실패 | 채점 상세와 실행 로그를 확인해 빠뜨린 요구사항을 지침에 보완한다. |
| 채점 대기 | 잠시 후 6번으로 다시 확인한다. |
| 조건 다름 또는 비교 제외 | 실행 조건과 진단 내용을 확인하고 강사에게 문의한다. |

필요하면 **지침 수정 → 3번 실행 → 5번 기법 기록 → 6번 채점 수신 → 4번 비교**를 반복합니다. 토큰이 늘어난 실행과 실패한 실행도 실험 기록으로 남깁니다. 통과 여부를 유지하지 못한 실행은 절감 성과로 인정하지 않습니다.

모델·추론 설정 등 공통 실행 조건은 수업 중 임의로 바꾸지 않습니다. 운영 규정·데이터·실행 중의 작업 지침·테스트 보조 도구는 고정하며, 기능 구현에 필요한 API 문서와 아키텍처 문서·ADR 갱신은 정상 작업으로 인정합니다.

## 7. 마감 전 확인과 결과 공유

실행마다 결과는 자동 제출됩니다. 수업 마감 전에는 공유할 기록에서 다음을 확인합니다.

- 제출 상태가 `제출됨`이다.
- 채점 상태가 `통과`이고 비교가 `가능`하다.
- 적용한 기법과 변경 이유가 기록되어 있다.
- 강사가 안내한 전체 결과 화면에 해당 기록이 보인다.

최신 실행이 항상 가장 좋은 결과일 필요는 없습니다. 이전 실행도 기록에 남으므로 공유할 실행의 ID를 함께 확인합니다. 이전 실행의 메모를 수정해야 한다면 강사에게 해당 실행 ID를 전달합니다.

발표는 관찰한 문제, 적용한 기법, 채점 결과, 입력 토큰 변화의 순서로 설명합니다.

> 테스트 성공 로그가 반복되는 것을 보고 출력 요약을 적용했습니다. 전체 테스트는 유지했고 채점도 통과했습니다. 입력 토큰이 어떻게 바뀌었는지 확인했고, 다음에는 문서 조회 범위를 조정해 보겠습니다.

전체 결과 화면은 참가자별 실행과 기법을 공유하는 용도이며 순위를 매기지 않습니다. 종료할 때는 메뉴 **0번**을 선택합니다.

## 문제가 생겼을 때

| 상황 | 수강생이 할 일 |
|---|---|
| 준비 확인 실패 | 표시된 안내를 확인하고 `doctor.log`를 강사에게 전달한다. |
| 최근 실행의 제출 실패 | 접속 문제를 해결한 뒤 5번으로 같은 실행을 재제출한다. |
| 채점 대기 | 6번으로 결과를 다시 가져온다. 오래 지속되면 강사에게 확인을 요청한다. |
| 실행 오류·시간 초과·구현 변경 없음 | 결과 화면의 최종 응답과 로그를 확인하고 강사에게 문의한다. 완료되지 않은 실행은 자동 제출하지 않는다. |
| 브라우저가 열리지 않음 | 실습 폴더의 `results.html`을 직접 연다. |
| 창을 닫았음 | 같은 폴더의 시작 파일을 다시 실행한다. 기존 지침과 기록을 유지한다. |

환경 설치와 운영 설정은 [강사용 준비 안내](instructor-setup.md), 개별 명령 사용법은 [README](../README.md)를 참고합니다.
