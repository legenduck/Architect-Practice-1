# 강의에서 배운 기법의 적용 힌트

Progressive disclosure 적용 결과를 확인한 뒤, 추가로 개선할 부분을 선택하는 참고 자료입니다. 제시된 항목을 모두 적용할 필요는 없습니다. 결과에서 관찰한 문제와 적용할 기법을 연결하고, 변경한 지침으로 다시 실행해 효과를 확인합니다.

## 작업별 라우팅

**살펴볼 내용:** 읽은 문서에 쿠폰 기능과 무관한 내용이 포함되어 있는지 확인합니다.

**적용 방향:** 현재 지침은 문서마다 언제 읽을지를 안내합니다. 쿠폰 계산, 출력 형식 변경 등 작업 종류별로 필요한 문서와 절을 더 좁혀 지정할 수 있습니다. 필요한 정보가 부족할 때 원문을 추가로 조회하는 경로도 남깁니다.

**판단할 점:** 무조건 적은 문서를 읽도록 제한하면 필요한 규칙을 놓칠 수 있습니다. 문서 경로의 수뿐 아니라 채점 결과와 입력 토큰 총량을 함께 비교합니다.

## 규정 요약

**살펴볼 내용:** 작업에 필요한 규칙보다 배경 설명과 계산 예가 반복해서 입력되는지 확인합니다.

**적용 방향:** 반복해서 필요한 규칙은 작업 지침에 간결하게 정리하고, 해당 규정의 원문 경로와 조항을 남길 수 있습니다. 요약에서 제외할 설명과 반드시 남겨야 할 조건을 선택합니다.

**판단할 점:** 짧게 만드는 과정에서 예외나 적용 순서가 사라질 수 있습니다. 요약과 원문을 대조하고 채점 결과를 확인합니다. 요약을 만드는 대화는 과제 실행과 별도로 진행합니다.

## 테스트 출력 줄이기

**살펴볼 내용:** 전체 테스트 출력이 반복해서 입력되어 토큰이 늘어나는지 확인합니다.

**적용 방향:** 테스트 실행은 유지하면서 상세 결과를 파일에 저장하고, Codex에는 통과 여부와 실패한 항목 등의 요약만 보여 줄 수 있습니다. 어떤 정보를 요약에 남길지, 언제 상세 로그를 조회할지 정합니다.

실습 저장소의 `tools/test_summary.py`는 전체 테스트를 실행하고 상세 출력을 `.practice-test-logs/`에 저장하는 보조 도구입니다. 적용하는 경우 작업 지침의 테스트 명령을 이 도구를 사용하도록 바꿀 수 있습니다.

```bash
python tools/test_summary.py
```

**판단할 점:** 출력량이 줄었어도 필요한 테스트가 빠졌다면 개선으로 보지 않습니다. 오류가 발생한 경우 요약만으로 원인을 알 수 있는지, 상세 로그를 추가로 확인해야 하는지도 검토합니다.

## 스킬로 분리

**살펴볼 내용:** 특정 작업에서만 필요한 긴 절차가 기본 지침에 항상 들어가는지 확인합니다.

**적용 방향:** 항상 필요한 지침은 `AGENTS.md`에 남기고, 쿠폰 작업에만 필요한 절차를 `edit/.agents/skills/스킬이름/SKILL.md`로 분리할 수 있습니다. 스킬에는 언제 사용하는지 설명하고, 필요한 원문 경로를 연결합니다. 형식과 활성화 방법은 연구원이 확인한 사내 Codex 안내를 따릅니다.

**판단할 점:** 파일을 옮겼다는 사실만으로 입력 토큰이 줄었다고 판단할 수 없습니다. 실제로 필요한 시점에 스킬을 사용했는지 실행 기록으로 확인합니다.

## 결과를 비교할 때

적용한 기법과 수정 이유를 기록합니다. 같은 과제와 초기 코드로 다시 실행한 뒤 채점 통과 여부와 입력 토큰을 비교합니다. 여러 기법을 동시에 적용했다면 각각의 효과를 구분하기 어려울 수 있으므로, 필요한 경우 변경 범위를 나누어 비교합니다.
