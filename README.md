# 실습 1: Coding Agent의 입력 context 줄이기

같은 쿠폰 기능 추가 과제를 Codex에 반복해서 맡기고, 작업 지침에 따라 입력 토큰이 어떻게 달라지는지 비교합니다. 직접 수정할 대상은 `edit/AGENTS.md`와 필요한 경우의 스킬입니다. 기능 구현은 실행 도구가 Codex에 요청합니다.

| 시간 | 진행 |
|---|---|
| 11:00–11:30 | 실습 소개와 환경 설정 |
| 11:30–12:30 | 기본 지침 비교와 직접 개선 |
| 12:30–13:30 | 점심, 13:25까지 결과 제출 |
| 13:30–14:00 | 적용 기법별 결과 공유 |

## 처음 시작할 때

연구원이 참여 권한을 부여한 GitHub 계정으로 저장소를 받습니다.

```bash
git clone https://github.com/legenduck/Architect-Practice-1.git
cd Architect-Practice-1
```

이 README와 `lab.py`가 있는 폴더에서 터미널을 엽니다. Python 3.10 이상, Git, 사내에서 허용된 Codex CLI와 계정 로그인이 필요합니다. Codex 설치와 로그인은 연구원의 사내 환경 안내를 따릅니다. API 키를 발급하거나 입력하는 과정은 없습니다.

macOS 또는 Linux:
```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lab.txt
python lab.py init
python lab.py enroll p01
```

Windows PowerShell:
```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-lab.txt
python lab.py init
python lab.py enroll p01
```

`p01`은 예시입니다. 연구원이 배정한 참가자 번호를 사용합니다. `enroll` 명령이 `students/참가자번호` 브랜치를 선택하며, 기존 코드나 지침을 지우지 않습니다. 첫 제출 전에 Git의 사용자 이름과 이메일, GitHub push 권한이 준비되어 있어야 합니다. 설정은 연구원의 사전 안내를 따릅니다.

설정이 완료된 교육용 PC에서는 연구원이 안내한 환경 활성화 이후 `python lab.py doctor`부터 확인합니다. 설치나 로그인 오류가 나면 오류 화면을 유지하고 연구원에게 요청합니다.

참가자 번호는 브랜치 선택 시 `config.json`에 저장됩니다. 모델과 프로필은 연구원이 배포한 설정으로 지정하고 `python lab.py doctor`로 확인합니다. 모델을 바꾸면 이전 실행과 같은 조건의 비교가 되지 않습니다.

## 기본 작업 지침으로 실행

```bash
python lab.py run baseline --submit --wait 120
```

실행 도구가 초기 코드를 복사하고 문서 원문을 포함한 작업 지침을 넣은 다음, 새 Codex 대화에서 고정 과제 요청문을 실행합니다. 이미 구현된 코드를 다음 실험에 이어 쓰지 않습니다.

실행이 끝나면 `results.html`을 브라우저로 엽니다. 입력 토큰 총량과 채점 상태를 확인합니다. `채점 대기`는 통과가 아니므로 토큰 절감 비교에 포함하지 않습니다. 결과 파일이 개인 브랜치로 푸시되면 중앙 수집기가 채점합니다. 최대 120초 동안 결과를 기다린 뒤, 아직 대기 중이면 아래 명령으로 다시 가져옵니다.

```bash
python lab.py sync
```

## Progressive disclosure를 적용한 지침으로 실행

```bash
python lab.py run disclosure --submit --wait 120
```

이번에는 문서 본문 대신 문서 목록과 조회 시점을 담은 `AGENTS.example.md`를 사용합니다. 문서를 필요할 때 조회하도록 바꾼 효과를 비교하기 위해 과제, 초기 코드, 모델과 테스트 출력 명령은 동일하게 유지합니다.

`results.html`을 새로고침합니다. 두 실행이 모두 채점에 통과했는지 확인한 뒤 입력 토큰 총량을 비교합니다. 호출별 기록이 수집된 경우에는 첫 호출과 이후 사용량도 확인합니다.

## 강의에서 배운 기법으로 직접 개선

1. 결과에서 불필요한 문서 조회나 긴 테스트 출력이 있었는지 확인합니다.
2. [기법별 적용 힌트](guides/techniques.md)를 참고해 개선할 부분과 적용할 기법을 선택합니다.
3. Codex에서 `edit` 폴더를 열고 `AGENTS.md`의 수정을 요청합니다. 이 폴더는 지침을 개선하는 공간이며, 여기서 나눈 대화의 토큰은 과제 실행에 합산하지 않습니다.
4. 지침을 저장한 뒤 터미널에서 아래 명령을 실행합니다.

```bash
python lab.py run custom --submit --wait 120
```

실행 도구는 `edit/AGENTS.md`와 `edit/.agents/skills`만 가져오고, 구현 코드는 다시 초기 상태에서 시작합니다. 이전에 생성한 코드를 `edit`로 복사하거나 직접 초기화할 필요가 없습니다.

`results.html`에서 수정 전 결과와 비교합니다. 통과 여부를 유지하면서 입력 토큰이 줄었는지 확인하고, 필요하면 지침을 보완해 다시 실행합니다. `edit` 폴더를 삭제하거나 초기 지침으로 덮어쓰지 않으면 개선 내용은 유지됩니다.

## 결과 확인

| 확인할 내용 | 해석 |
|---|---|
| 총 입력 토큰과 채점 결과 | 같은 실행 조건에서 통과한 기록끼리 비교합니다. 캐시 입력도 입력 총량에 포함하며 별도로 더하지 않습니다. |
| 호출별 입력 토큰 | 세부 기록을 수집하고 총량과 일치하는 경우 표시합니다. 세부 값이 없으면 미제공으로 표시합니다. |
| 명령에 나타난 문서 경로 | 명령에서 발견한 경로를 보여 줍니다. 실제 읽기 범위는 원본 명령과 함께 확인합니다. |
| 채점 실패 | 절감 결과로 인정하지 않고 지침을 보완한 뒤 다시 실행합니다. |
| 실행 오류 또는 측정 누락 | 기록을 유지하고 연구원에게 확인을 요청합니다. |

결과 파일은 실험 순서로 표시합니다. 다른 참가자와 순위를 비교하지 않습니다.

## 13:25까지 결과 제출

실행 도구가 `submissions/실행ID.zip`에 구현 결과, 작업 지침과 사용량 기록을 모읍니다. 제출 명령은 이 파일만 커밋하고 본인의 `students/참가자번호` 브랜치로 푸시합니다. 다른 변경사항을 함께 올리지 않습니다.

직접 개선한 실행을 제출할 때 적용한 기법과 변경 내용을 기록합니다.

```bash
python lab.py submit --technique "작업별 라우팅" --note "쿠폰 작업에서 읽을 문서의 범위를 조정" --wait 120
```

여러 기법을 적용했다면 `--technique`를 여러 번 지정할 수 있습니다. 이전 실행은 `--run 실행ID`로 선택합니다. 실행할 때 `--submit`을 쓰지 않았거나 수동으로 Git을 사용하는 경우에도, 같은 `submissions/` 폴더의 결과 ZIP을 개인 브랜치에 푸시하면 중앙에서 수집합니다.

```bash
python lab.py sync
```

이 명령으로 `results` 브랜치의 채점 결과를 가져오고 `results.html`을 갱신합니다. 채점 결과는 제출 파일과 연결되어 있으므로, 수정한 새 제출에 이전 결과를 재사용하지 않습니다.

- [전체 제출 현황](https://github.com/legenduck/Architect-Practice-1/tree/results)
- 제출 후 `main`으로 병합하거나 Pull Request를 만들 필요는 없습니다.
- 인증이나 push 오류가 발생하면 실행 기록을 보존하고 연구원에게 확인을 요청합니다. 강제 push로 해결하지 않습니다.
- 이 저장소는 공개되어 있습니다. 제공된 가상 과제와 실습 결과만 사용하고 회사 코드나 개인 업무 자료는 넣지 않습니다.

13:30에는 적용한 기법, 변경한 지침, 채점 결과와 입력 토큰의 변화를 공유합니다. 중앙에서 기법별로 결과를 확인하며 순위를 매기지 않습니다.
